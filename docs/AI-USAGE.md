# AI 使用与验证记录

本产品为「AI Native」工作台：AI 能力贯穿研发过程与产品运行时两条线，全部可验证。

## 1. 研发过程中的 AI 使用（Trae + GLM）

| 环节 | AI 用途 | 人工验证方式 |
|---|---|---|
| 数据源调研 | 读取扶摇 `llms-full.txt`、iFinD SKILL 文档，归纳端点/参数/返回结构 | 用 curl / node 脚本对每个关键端点实测（快照、历史K线、财务指标、标的检索、EDB、资讯检索） |
| API 探测 | 生成探测脚本，保存真实返回样本 | 逐份人工核对返回字段（date_ms/close_price、abilities[].indicators[].index_id、EDB attrs.unit/data_source） |
| 代码实现 | 生成全部源码（客户端/引擎/前端） | `npm run build` 类型检查 + 端到端 SSE 实测 3 组样本 |
| 解析器校准 | 依据实测返回修正：EDB 结构化数组解析、iFinD 资讯 `data.data` 为 JSON 字符串、条目中文键名（资讯标题/日期）、行情口径为前复权 | 重跑样本，逐条核对判定结果与偏差 |
| 测试设计 | 设计正/负/合规三组测试样本 | 见 docs/TESTING.md，全部通过 |

关键经验（防幻觉三原则）：
1. **LLM 只拆解不比对**——数值核验（偏差、容差、单位换算）全部由代码完成；
2. **提示词强约束**——quote 必须逐字摘自原文、metric 枚举化、unit 白名单、period 正则归一化；
3. **解析失败即降级**——任何解析/取数失败输出"无法核实/取证失败"，绝不猜测。

## 2. 产品运行时的 AI 能力

| 能力 | 模型/服务 | 输入 → 输出 | 验证 |
|---|---|---|---|
| 论断拆解 | DeepSeek chat（JSON Mode，temperature=0.1） | 研报文本 → 结构化 claims（类型/主体/指标/数值/单位/日期/报告期/比较方向） | 样本 1/2 拆解结果逐条人工核对：数值、单位、报告期、quote 逐字一致 |
| 合规复扫 | DeepSeek chat（JSON Mode） | 文本 → 违规表述（规则+依据+理由） | 样本 3 命中 5 条细粒度定位，与规则引擎 3 条互补去重 |
| 数据取证 | 扶摇 REST + iFinD MCP（**非 LLM**，代码直连） | claim → 参数化 API 调用 → 原始返回 | 每条结论证据卡片含原始返回截断 + request_id，可回溯 |

**AI 不做的事**（合规边界）：不生成核验数值、不修改论断原文、不输出投资建议/预测、不在数据缺失时兜底"正常"结论。

## 3. 可复现验证步骤

```bash
npm install && npm run dev
# 依次点击三个内置样例 → 开始核验
# 样例1：5 条事实论断全部"已核实"，观点正确归类
# 样例2：3 条错误数值全部"冲突"并给出偏差；"创年内新高"→"无法核实"
# 样例3：8 条合规发现（规则 3 + LLM 5），附监管依据
# 每条结论点开"查看证据"核对：数据源/接口/参数/request_id/时间/单位/口径/原始返回
```
